## 1. 전체 구성

```
 사용자 폰 (Chrome / Safari)
   │  HTTPS
   ▼
 Vercel (호스팅·서버 실행)
   ├─ 화면: Next.js 페이지 (/, /detail, /favorites, /search, /welcome)
   └─ 서버 API (Route Handler, 결과 캐시)
        ├─ /api/weather      ──▶ Open-Meteo Forecast API   (날씨)
        ├─ /api/geo/search   ──▶ Nominatim 또는 Kakao Local (지역 검색)
        └─ /api/geo/reverse  ──▶ Nominatim 또는 Kakao Local (좌표 → 동 이름)

 GitHub 저장소 ──push──▶ Vercel 자동 빌드·배포
```

- 사용자 폰은 **우리 서버(Vercel)하고만** 통신한다. 외부 API는 서버가 대신 호출하므로 외부 서비스에 사용자 IP가 전달되지 않고, API 키도 폰에 노출되지 않는다.
- 데이터베이스는 없다. 즐겨찾기 등 사용자 데이터는 각자 폰의 브라우저(localStorage)에 저장한다.

## 3. 외부 서비스

| 서비스 | 용도 | 요금제 | 인증 | 이용 조건·한도 |
|---|---|---|---|---|
| **Vercel** | 호스팅, 서버 API 실행, HTTPS, 자동 배포 | Hobby (무료) | GitHub 계정 연동 | 개인·비상업용. 월 사용량 한도 있음(대시보드 **Usage**에서 확인) |
| **GitHub** | 소스 저장소 | Free | 계정 `bskimways1` | 비공개 저장소 |
| **Open-Meteo Forecast API** | 어제·오늘 시간별 기온·하늘 상태 | 무료 | 없음 | **비상업용**, 하루 1만 회 이하 권장 |
| **OpenStreetMap Nominatim** | 지역 검색, 좌표 → 동 이름 (기본값) | 무료 | 없음 (User-Agent 필수) | **초당 1회 이하, 자동완성 금지**. 서버에서 1.1초 간격으로 줄 세워 호출 |
| **Kakao Local API** | 지역 검색, 좌표 → 법정동 (선택) | 무료 한도 | REST API 키 | 키를 설정하면 Nominatim 대신 사용. 현재 미설정 |
| **jsDelivr CDN** | Pretendard 글꼴 파일 | 무료 | 없음 | — |

### Open-Meteo 호출 방식
```
GET https://api.open-meteo.com/v1/forecast
    ?latitude=…&longitude=…
    &hourly=temperature_2m,weather_code,is_day
    &past_days=1&forecast_days=1&timezone=auto
```
`past_days=1` 로 한 번에 48개(0~23 = 어제, 24~47 = 오늘) 시간별 값을 받는다. 어제 값은 모델 분석값, 오늘 값은 예보값이다.

## 4. 서버 API (우리 서비스)

| 엔드포인트 | 입력 | 출력 | 캐시 |
|---|---|---|---|
| `GET /api/weather` | `points=위도,경도;위도,경도…` (최대 20개) | 지점별 `{ yesterday[24], today[24], 날짜, 현지 시차, 출처 }` | 지점(소수 2자리 ≈ 1km) + 서울 날짜. 15분마다 갱신, 최대 1시간 |
| `GET /api/geo/search` | `q=검색어` (최대 40자) | 지역 목록 `{ name, label, sub, lat, lon }` | 검색어 단위 하루 |
| `GET /api/geo/reverse` | `lat`, `lon` | 지역 1개 (동 이름) | 좌표(소수 3자리 ≈ 100m) 하루 |

- 캐시는 Next.js `'use cache'` + `cacheLife` 로 처리하며, Vercel 서버 메모리에 저장된다.
- 오류 시 `{ error: "메시지" }` 와 함께 400(입력 오류) / 502(외부 API 오류)를 돌려준다.

## 6. 확장 설계: 기상청 API로 전환

날씨 데이터는 `WeatherProvider` 인터페이스 뒤에 숨겨 두었다. 화면은 공통 형식(`DayComparison`)만 사용하므로 제공자만 바꾸면 된다.

```ts
interface WeatherProvider {
  id: string;
  getComparisons(points: LatLon[]): Promise<DayComparison[]>;
}
```

전환 절차:
1. `lib/weather/kma.ts` 에 구현 — 어제 24시간은 **ASOS 시간자료**(관측), 오늘 24시간은 **단기예보**를 받아 `DayComparison` 으로 변환. 하늘 상태는 WMO 코드로 바꿔 `weatherCode` 에 넣는다. 위경도 → 기상청 격자(nx, ny) 변환과 가까운 ASOS 관측소 매핑이 필요하다.
2. `lib/weather/index.ts` 의 `providers` 에 등록.
3. 환경변수 `WEATHER_PROVIDER=kma` 와 공공데이터포털 서비스 키 설정.

지역 제공자도 같은 구조(`GeoProvider`)다. `KAKAO_REST_API_KEY` 만 넣으면 Kakao로 바뀐다.

### 브랜치·배포 흐름
```
작업 브랜치 (feat/…, fix/…, docs/…)
   └─ 확인 후 main 에 병합 ──push──▶ Vercel 이 main 을 자동 빌드 (약 30초~1분)
                                    └─ Production 주소에 반영
```
- main 에 push하면 자동으로 운영에 반영된다.
- main 이 아닌 브랜치를 push하면 Vercel이 별도 **미리보기 주소**를 만든다(기본적으로 Vercel 로그인 필요).
- 배포 이력과 되돌리기: Vercel 대시보드 **Deployments** → 이전 배포의 `⋯` 메뉴 → **Instant Rollback**(또는 **Promote**)으로 예전 버전을 운영에 다시 올린다.
