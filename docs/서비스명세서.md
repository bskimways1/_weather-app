## 1. 전체 구성

```
 사용자 폰 (Chrome / Safari)
   │  HTTPS
   ▼
 Vercel (호스팅·서버 실행)
   ├─ 화면: Next.js 페이지 (/, /detail, /favorites, /search, /welcome)
   └─ 서버 API (Route Handler, 결과 캐시)
        ├─ /api/weather      ──▶ Open-Meteo Forecast API   (날씨)
        ├─ /api/geo/search   ──▶ Nominatim 또는 Kakao Local (지역 검색)
        └─ /api/geo/reverse  ──▶ Nominatim 또는 Kakao Local (좌표 → 동 이름)

 GitHub 저장소 ──push──▶ Vercel 자동 빌드·배포
```

**Live 사이트**는 같은 저장소의 `feat/realtime` 브랜치를 별도 Vercel 프로젝트로 배포한다. 차이점:

```
 Vercel (서울 icn1 지역에서 실행)
   └─ /api/weather ──▶ 기상청 API허브 (AWS 1분 관측·지점정보·초단기/단기예보)
                   └─▶ Open-Meteo (하늘 상태·낮밤, 기상청 실패 시 대체)
        └─ Vercel Runtime Cache (공유 캐시: 모든 요청·사용자가 함께 씀)
```

- 사용자 폰은 **우리 서버(Vercel)하고만** 통신한다. 외부 API는 서버가 대신 호출하므로 외부 서비스에 사용자 IP가 전달되지 않고, API 키도 폰에 노출되지 않는다.
- 데이터베이스는 없다. 즐겨찾기 등 사용자 데이터는 각자 폰의 브라우저(localStorage)에 저장한다.

### Open-Meteo 호출 방식
```
GET https://api.open-meteo.com/v1/forecast
    ?latitude=…&longitude=…
    &hourly=temperature_2m,weather_code,is_day
    &past_days=1&forecast_days=1&timezone=auto
```
`past_days=1` 로 한 번에 48개(0~23 = 어제, 24~47 = 오늘) 시간별 값을 받는다. 어제 값은 모델 분석값, 오늘 값은 예보값이다.

## 4. 서버 API (우리 서비스)

| 엔드포인트 | 입력 | 출력 | 캐시 |
|---|---|---|---|
| `GET /api/weather` | `points=위도,경도;위도,경도…` (최대 20개) | 지점별 `{ yesterday[24], today[24], 날짜, 현지 시차, 출처 }`. Live 는 `live`(지금 관측 기온·관측 시각·어제 같은 분·관측소 목록)와 `observedThroughHour`(오늘 몇 시까지 관측값인지)도 | 지점(소수 2자리 ≈ 1km) + 서울 날짜. 15분마다 갱신, 최대 1시간 (Live 는 1분) |
| `GET /api/geo/search` | `q=검색어` (최대 40자) | 지역 목록 `{ name, label, sub, lat, lon }` | 검색어 단위 하루 |
| `GET /api/geo/reverse` | `lat`, `lon` | 지역 1개 (동 이름) | 좌표(소수 3자리 ≈ 100m) 하루 |

- 캐시는 Next.js `'use cache'` + `cacheLife` 로 처리하며, Vercel 서버 메모리에 저장된다.
- **주의(서버리스)**: Vercel 서버 메모리는 요청이 끝나면 사라질 수 있어 `'use cache'` 만으로는 요청 간에 재사용되지 않는다. Live 사이트는 기상청 호출 한도 때문에 공유해야 하는 값을 `'use cache: remote'`(Vercel Runtime Cache)에 둔다. 읽기 횟수를 아끼려고 큰 값(전국 관측소 목록 약 150KB)은 넣지 않고, "지점별 근처 관측소", "관측소별 하루 정시값"처럼 작게 나눠 저장한다.
- 오류 시 `{ error: "메시지" }` 와 함께 400(입력 오류) / 502(외부 API 오류)를 돌려준다.

## 6. 확장 설계: 기상청 API로 전환 (Live 사이트에서 구현 완료)

날씨 데이터는 `WeatherProvider` 인터페이스 뒤에 숨겨 두었다. 화면은 공통 형식(`DayComparison`)만 사용하므로 제공자만 바꾸면 된다. 기상청 제공자는 `feat/realtime` 브랜치에 구현돼 Live 사이트에서 쓰고 있다(6.1).

```ts
interface WeatherProvider {
  id: string;
  getComparisons(points: LatLon[]): Promise<DayComparison[]>;
}
```

지역 제공자도 같은 구조(`GeoProvider`)다. `KAKAO_REST_API_KEY` 만 넣으면 Kakao로 바뀐다.

### 6.1 기상청 제공자 (`WEATHER_PROVIDER=kma`)

기상청 API허브(apihub.kma.go.kr) 인증키 하나로 모두 받는다. 공공데이터포털 키는 쓰지 않는다.

| 쓰는 API | 경로 | 용도 | 호출 빈도 (공유 캐시 기준) |
|---|---|---|---|
| AWS 지점정보 | `typ01/url/stn_inf.php?inf=AWS` | 관측소 약 745곳의 위치 | 지점별 근처 관측소를 하루 1회 계산할 때 |
| AWS 매분자료 (전국) | `typ01/cgi-bin/url/nph-aws2_min?stn=0` | 지금 기온(전국 최신 1분), 어제 같은 분 | 사용 중일 때 1분에 1회씩 |
| AWS 매분자료 (1곳, 하루) | `…nph-aws2_min?stn=ID&tm1=…0000&tm2=…HH00` | 관측소별 어제·오늘 정시값 | 관측소마다 어제 1회, 오늘 정시마다 1회 |
| 초단기예보 | `typ02/openApi/VilageFcstInfoService_2.0/getUltraSrtFcst` | 앞으로 6시간 기온·하늘 | 격자별 매시 |
| 단기예보 | `…/getVilageFcst` | 오늘 남은 시간 기온·하늘 | 격자별 3시간마다 |

계산 방식:
- **근처 관측소**: 반경 10km 안 가까운 순 최대 6곳(없으면 20km 안 1곳). 시간별 값은 가까운 4곳만 받는다.
- **거리 가중 평균**: 값이 있는 가까운 3곳을 `1/거리` 비율로 평균. 지금 기온·어제·오늘 지난 시각 모두 같은 방식.
- **격자 변환**: 위경도 → 기상청 동네예보 격자(nx, ny), 기상청 공식 Lambert 변환식(`toGrid`).
- **하늘 상태**: 관측소에는 구름 정보가 없어 관측 시각은 Open-Meteo 값을 쓰고, 실제 강수 관측(60분 강수 ≥ 0.1mm)이면 비(영하면 눈)로, 강수가 없는데 모델이 비라고 하면 흐림으로 바로잡는다. 예보 시각은 기상청 하늘상태(SKY)·강수형태(PTY)를 WMO 코드로 바꾼다.
- **대체**: 근처에 관측소가 없거나(해외) 기상청 호출이 실패하면 Open-Meteo 결과를 그대로 쓴다.
- **응답 형식**: 관측값 한글 주석은 EUC-KR이라 깨질 수 있으나 숫자 행만 쓰므로 문제없다. 기온 −50 이하는 결측.

### 브랜치·배포 흐름
```
작업 브랜치 (feat/…, fix/…, docs/…)
   └─ 확인 후 main 에 병합 ──push──▶ Vercel 이 main 을 자동 빌드 (약 30초~1분)
                                    └─ Production 주소에 반영
```
- main 에 push하면 자동으로 운영에 반영된다.
- main 이 아닌 브랜치를 push하면 Vercel이 별도 **미리보기 주소**를 만든다(기본적으로 Vercel 로그인 필요).
- 배포 이력과 되돌리기: Vercel 대시보드 **Deployments** → 이전 배포의 `⋯` 메뉴 → **Instant Rollback**(또는 **Promote**)으로 예전 버전을 운영에 다시 올린다.

## 9. 운영 조건과 비용

| 항목 | 현재 (시범 운영) | 상업 서비스로 공개할 때 |
|---|---|---|
| 호스팅 | Vercel Hobby, 0원 (사이트 2개 모두. 사용량은 계정 하나로 합산) | Vercel Pro 필요 (유료) |
| 날씨 | 기본: Open-Meteo 무료 / Live: 기상청 API허브 무료 (+ Open-Meteo 보조) | 기상청 API(무료, 상업 이용 가능). Open-Meteo 보조를 계속 쓰면 유료 플랜 |
| 공유 캐시 (Live) | Vercel Runtime Cache, Hobby 무료 한도 안 (예상 사용량 한도의 10~20%) | Pro 에서는 사용량만큼 과금 |
| 지역 | Nominatim 무료 | Kakao Local API |
| 관리 작업 | 없음. 서버·HTTPS 인증서·재시작은 Vercel이 처리 | 동일 |
| PC 필요 여부 | **필요 없음.** 코드를 고칠 때만 사용 | 동일 |

서비스가 멈추는 경우: Vercel 프로젝트·계정 삭제, 무료 사용량 초과, 외부 API(Open-Meteo·Nominatim·기상청) 장애 또는 정책 변경. Live 사이트는 기상청이 안 되면 Open-Meteo 로 대신 보여 주고, 공유 캐시 한도를 넘으면 느려지기만 한다(과금 없음). 기상청 활용신청은 2028-11-05 까지라 그 전에 연장한다.

## 10. 보안·개인정보

| 항목 | 내용 |
|---|---|
| 수집 정보 | 위치 좌표만 (약 100m 단위로 반올림 후 전송). 회원·연락처·기기 정보 수집 없음 |
| 서버 기록 | Vercel 요청 로그에 반올림된 좌표와 접속 IP가 짧은 기간 남음. 열람은 Vercel 계정 소유자만 |
| 외부 전달 | Open-Meteo·Nominatim·기상청 에는 우리 서버가 요청하므로 사용자 IP가 전달되지 않음. 기상청에는 좌표가 아니라 관측소 번호·예보 격자 번호만 보냄 |
| 사용자 데이터 | 즐겨찾기·검색어는 각 폰 브라우저에만 저장 |
| 비밀값 | API 키(기상청 인증키 포함)는 서버 환경변수로만 관리, 폰으로 내려가지 않음. `.env*` 는 git 제외. 기상청 인증키는 약관상 본인만 사용 |
| 계정 보안 | Vercel 계정은 2단계 로그인(2FA) 권장 — 인증키가 Vercel 설정에 보관됨 |
| 통신 | 전 구간 HTTPS |
